## 6. 真实 PostgreSQL 规则测试

| 场景 | 结果 | 核心证据 |
| --- | --- | --- |
| 首次绑定 | 通过 | `first_activated`，窗口次数仍为 0，分钟不变 |
| 同环境进入 | 通过 | `already_active`，不新增成功历史，不触发 60 秒 |
| 第一次重新绑定 | 通过 | `rebound`，0 → 1，令牌轮换，分钟不变 |
| 60 秒限制 | 通过 | 第三个环境返回 `rate_limited`，次数仍为 1 |
| 第 10 次 | 通过 | 允许，窗口次数变为 10 |
| 第 11 次 | 通过 | `window_limit_reached`，成功次数不增加并返回 `nextAvailableAt` |
| 滚动 15 天恢复 | 通过 | 超出窗口的最早记录不再占额度，新请求允许 |
| 幂等 | 通过 | 相同请求 ID 第二次返回 `replayed: true`，不重复计数或轮换令牌 |
| 并发 | 通过 | 两个独立数据库连接并发；结果为一次 `rebound`、一次 `rate_limited` |
| 事务回滚 | 通过 | 在成功日志写入阶段强制报错；环境、次数、令牌、日志、分钟全部恢复 |
| 管理员重置 | 通过 | 环境和令牌重置，原因留痕，不占用户窗口次数、不扣分钟 |

并发测试耗时 24 ms，成功记录只增加 1 条，没有死锁。事务回滚使用临时触发器在函数中途主动抛错，以验证真实数据库原子性，不是静态文本检查。

## 7. 使用方法

准备一次性的本地运行依赖后，执行：

```bash
V09_PG_RUNTIME_DIR=/private/tmp/codex-v09-pg-runtime \
V09_PG_PORT=55439 \
node scripts/db-acceptance/run-isolated-v09.mjs
```

程序仅允许本机回环地址，自动创建、启动、停止并删除临时数据库。任何一项断言失败都会以非零状态退出。

## 8. 限制与上线门禁

- 本次 19 个访问码是覆盖生产数据形态的脱敏构造数据，不是对生产 19 行数据的读取或复制。

- 本次隔离数据库执行本身不覆盖实体设备；相关 Preview、真实 Qwen、同环境恢复、重新绑定和接管核心验收已在后续阶段完成。
- 生产迁移前仍必须对真实 19 个访问码执行只读快照，并在迁移后立即自动对比。

因此本文只证明隔离数据库部分通过；是否进入生产仍以 Release Candidate 审核和正式发布清单为准。
