# 优化前复盘：监督请求取消与旧响应隔离

> 日期：2026-07-30
> 状态：工程与功能验收完成，Known Limitation 已接受
> 负责人：项目负责人 / Codex
> 关联范围：监督页、分析接口、心跳接口、分析结果持久化、测试环境验收

## 1. 当前基线

- 当前产品阶段：生产保持 v0.8；v0.9 已完成隔离数据库、独立测试部署和部分真机重新绑定验收，尚未满足生产上线条件。
- 当前代码/版本：`codex/device-rebind-mvp`，应用版本 0.9.0；工作树保留 v0.9 尚未提交的实现和验收文档。
- 与本次相关的现有流程：监督页定时发送分析和心跳；重新绑定在数据库事务中轮换活跃会话令牌；旧页面在下一次 401 后停止摄像头、清理本地状态并返回首页。
- 已确认事实：
  - 真机“监督中被新环境接管”没有形成双端持续监督，旧电脑心跳收到 401 后返回首页；
  - 前端已停止摄像头、校准定时器、常规分析定时器和心跳定时器；
  - 当前分析和心跳请求没有 `AbortController`；
  - 当前分析接口只在模型调用前校验一次会话；模型完成后直接写 `records` 和 `ai_call_logs`；
  - 测试环境本次回退到 Mock，尚未覆盖真实 Qwen 长请求；
  - 重新绑定规则固定为滚动 15 天 10 次、成功间隔 60 秒、免费且不扣监督时长。
- 判断或假设：
  - 浏览器取消可以减少无效工作，但不能单独证明服务端已经停止；
  - 服务端必须在持久化时再次以会话令牌进行原子校验，才能避免旧分析结果影响新环境。
- 未知项：
  - Vercel 对客户端断开信号传递到 Qwen 上游请求的稳定程度；
  - 真实 Qwen 长请求在微信和系统浏览器中的取消时延。

## 2. 触发问题

- 发生了什么：旧页面会退出，但已发出的请求无法主动取消；旧分析若在重新绑定前通过鉴权，可能在令牌轮换后才完成并写数据库。
- 证据来源：2026-07-30 真机服务端日志、测试数据库时间线和代码审计。
- 影响的角色：使用手机/电脑监督的家长和孩子、排查重复记录的运营人员。
- 影响的核心流程：分析请求 → 模型调用 → 记录持久化 → 提醒 → 新环境恢复监督。
- 影响的业务/质量指标：旧环境停止率、重复/过期识别记录、报告可信度、模型成本和接管体验。
- 不处理的后果：慢模型或弱网下可能出现旧结果晚写、旧响应更新本地状态，无法把“接管后立即失效”判定为完全通过。

## 3. 本次目标

- 目标：主动取消监督中的异步请求，并在前端和服务端双重隔离旧响应。
- 成功标准：
  - 新分析开始前取消上一分析；
  - 结束、重新绑定、卸载和返回首页时取消分析与心跳；
  - `AbortError` 不展示、不重试、不计为失败；
  - 旧响应不能更新提醒、状态、记录列表或报告状态；
  - 服务端旧令牌的分析结果不能写 `records`、`ai_call_logs` 或模型失败日志；
  - 新环境可恢复同一会话，不创建重复会话、计时或报告。
- 本次范围：监督页请求控制、分析结果写入保护、自动测试、测试部署和测试环境核查。
- 明确不做：重新绑定次数/窗口/间隔、访问码权益、会话结算口径、账户体系、设备指纹、生产迁移或生产部署。

## 4. 规则与口径

- 需要确认的业务规则：无新增规则；继续使用单一激活环境和现有会话令牌轮换。
- 会变化的数据/指标口径：不变化；被取消或判定过期的分析不应成为识别记录或 AI 成功调用。
- 兼容旧数据的方式：不修改现有记录；新增持久化函数只保护新请求。
- 隐私、安全或权益影响：减少旧环境继续传图和写数据的风险；不修改任何监督分钟。

## 5. 方案摘要

- 建议方案：
  - 客户端为分析、心跳及结束后的报告请求保存 `AbortController`；
  - 使用请求序号、生命周期版本、会话 ID 和会话令牌判断响应是否仍有效；
  - 重新绑定、结束、卸载时统一失效请求生命周期；
  - 服务端把“会话令牌仍有效 + 写识别记录 + 写 AI 日志”放入同一数据库事务；
  - Qwen 请求使用客户端断开信号，取消不写异常日志。
- 备选方案：仅在模型返回后再次查询会话再写入。
- 选择理由：单次查询与写入之间仍有竞态，数据库事务保护更符合接管场景。
- 主要风险：客户端断开不保证所有托管环境立即终止服务端函数；数据库事务仍是最终写入门禁。
- 回滚/降级方式：回退应用代码和新增函数；新增函数不改变旧表和旧数据，生产保持 v0.8。

## 6. 验收与观察

- 功能验收：分析中接管、AbortError 静默、旧响应晚返回、新环境恢复、正常结束和报告。
- 异常路径：客户端取消后服务端仍完成、令牌在模型调用期间轮换、页面卸载、重复触发分析/心跳。
- 数据验证：无旧分析记录、无旧 AI 成功日志、无重复会话/分钟/报告。
- 设备/浏览器验证：先部署独立 v0.9 测试环境；再以真实 Qwen 长请求补充一次电脑→手机接管。
- 上线后观察指标：测试环境的 401、取消、识别记录和 AI 调用时间线。
- 观察窗口：Release Candidate 通过后按生产上线清单观察 401、旧请求写入、Qwen 错误率和成本。

## 8. 实施后回写

- 实际改动：
  - 监督页为分析、心跳、校准纠错和报告请求增加独立 `AbortController`；新分析开始、结束监督、被新环境接管、页面卸载及返回首页时统一取消相关请求。
  - `AbortError` 使用静默分支处理，不展示网络错误、不重试，也不写入异常页面状态。
  - 客户端以会话 ID、会话令牌、生命周期版本和请求序号隔离过期响应；提醒播放前后也会再次确认请求仍属于当前会话。
  - 分析接口把客户端取消信号继续传给 Qwen；取消不回退 Mock、不写模型异常。
  - 新增数据库事务函数，在持久化时锁定会话并复核会话状态与令牌，原子写入识别记录和 AI 调用日志；旧令牌返回失效结果且不写任何分析数据。
  - 心跳更新额外限定当前会话令牌，避免已通过早期鉴权的旧心跳在重新绑定完成后晚更新活动时间。
- 验证结果：
  - Release Candidate 整理后自动测试 58 项通过；TypeScript、Lint、生产构建和差异格式检查通过。
  - 本地真实 PostgreSQL 验证通过：旧令牌写入 0 条识别记录、0 条 AI 日志、0 条错误日志；新令牌可正常写入；会话始终 1 条，监督分钟和报告均未变化。
  - migration 19 已于 2026-07-30 在隔离 Supabase 项目 `STAGING_PROJECT_REF_REDACTED` 成功执行；只读核验确认函数存在、启用 `security definer`，仅 `service_role` 可执行。
  - 测试 Preview `PREVIEW_DEPLOYMENT_ID_REDACTED` 构建成功且状态为 Ready，固定验收地址已指向该 Preview；未执行生产迁移或部署。
- 与原方案的差异：会话结束结算请求没有在客户端主动中止，因为数据库可能已经原子提交，贸然取消只会让客户端丢失结算结果；分析、心跳、校准纠错和报告均已纳入取消或过期响应隔离。
- 遗留问题：真实 Qwen 上游已经开始处理后发生 Abort 时，无法实机证明连接立即终止。客户端和数据库已保证旧请求不影响数据、提醒、报告、状态、计时或权益；极端情况下可能多一次模型调用费用。
- 基线文档更新：已更新项目基线、业务现状、迭代机制、验收资料和复盘索引。
- 最终状态：工程与功能验收完成，Known Limitation 已接受为非阻断；生产保持 v0.8，当前进入 Release Candidate 整理。
