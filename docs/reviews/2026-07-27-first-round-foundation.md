# 优化前复盘：第一轮产品地基优化

> 日期：2026-07-27
> 状态：待部署
> 负责人：项目负责人 / Codex
> 关联范围：套餐权益、会话结算、报告、隐私、测试与部署

## 1. 当前基线

- 当前阶段：产品闭环较完整的 MVP，客户量较少，暂不建设支付和完整账户体系。
- 当前代码：`07f7d42`，项目基线文档尚在工作区。
- 当前流程：访问码创建 → 首次设备绑定 → 监督 → 前端提交结束数据 → 服务端结束会话 → 单独增加已用额度 → 报告。

### 已确认事实

- 所有套餐当前被统一设置为创建后三个月到期。
- 改套餐不会同步总时长和到期时间。
- 会话结束与额度扣减不是同一数据库事务。
- 服务端采用前端提交的结束时间、持续分钟和 AI 调用次数。
- 标准/高级报告接口仍生成 Mock 内容。
- 首页隐私说明与当前图片处理方式不完全一致，也没有记录确认版本。
- 仓库没有自动化测试、依赖锁文件和 CI。

### 负责人已确认的业务规则

- 所有套餐和体验卡都不设置使用期限。
- 只有进入监督后才计算使用时间，不使用时不扣时间。
- 只看总时长；总时长全部用完后才禁止继续访问。
- 原子结算按建议优化。
- 标准/高级 Mock 报告按建议优化。
- 隐私提示默认勾选，不增加额外操作。
- 工程质量能力可以先行优化。

### 实施解释

- “登录”在当前产品中等价于成功开始一段监督会话；仅打开首页或输入错误访问码不计时。
- 当前系统不持久保存截图，因此隐私说明将写成“单帧用于本次分析、Qwen 模式会发送给第三方模型、不保存视频和截图”，不再声称“24 小时后删除”。
- 默认勾选的隐私确认会记录说明版本和确认时间，但本轮不扩展为完整隐私中心。
- 数据库保留旧 `expires_at`、`daily_minutes` 字段用于兼容，业务逻辑不再使用有效期和每日额度。

## 2. 触发问题

- 套餐名称、有效期和总时长冲突，可能造成多给或少给权益。
- 非原子结算可能出现会话已结束但未扣额度，或并发覆盖。
- 未结算会话时长不计入剩余额度，可能超额使用。
- 前端可提交持续时长和 AI 次数，数据口径可被篡改或异常状态污染。
- Mock 报告不能作为正式套餐交付。
- 隐私声明中的“24 小时删除”“不对外共享”“用户可删除记录”与当前能力不完全一致。
- 没有测试和锁文件使后续维护成本和回归概率持续增加。

## 3. 本次目标

- 所有访问码永久有效，仅按总监督时长控制。
- 服务端根据数据库会话时间计时，不采用前端提交的计费数据。
- 会话完成和额度扣减在一个数据库函数中原子完成，并可安全重试。
- 总额度耗尽后停止核心监督调用。
- 所有套餐暂时交付同一套真实基础报告，不返回模拟趋势。
- 首页默认展示并勾选准确的隐私确认，服务端记录版本和时间。
- 增加关键业务规则测试、依赖锁文件和 CI。

### 明确不做

- 支付、订单、正式家庭账户。
- 每日额度和日重置业务。
- 标准/高级生成模型报告。
- 图片或视频持久存储。
- 完整管理员角色系统、持久化限流和大规模前端拆分。

## 4. 规则与口径

- 总剩余时长：`max(total_minutes - used_minutes, 0)`。
- 会话计时：从数据库 `sessions.start_time` 到服务端收到结束请求的时间；异常退出使用最后心跳时间。
- 计费分钟：向上取整，最低 1 分钟，但不得超过结算瞬间的剩余总分钟。
- 幂等：同一会话第二次及以后结算返回已处理，不再次扣减。
- 永久有效：不再读取 `expires_at`；迁移会把现有访问码的 `expires_at` 清空。
- 报告：统一 `basic`，只使用真实记录统计和真实习惯趋势。
- 隐私：当前不持久保存图片；Qwen 模式会发送单帧；保存监督记录和报告数据；确认版本写入会话。

## 5. 方案摘要

- 新增共享权益工具，统一剩余时长和服务端计时口径。
- 新增 Supabase `settle_study_session` 数据库函数，锁定会话和访问码后一次完成结算。
- 客户端结束请求不再决定持续分钟、AI 次数和报告等级。
- 服务端结算前只接受已属于该会话的记录 ID 更新，不接受前端补造新记录。
- 访问码创建不设置到期时间；套餐配置统一基础报告。
- 会话新增隐私说明版本和确认时间。
- 使用 Vitest 覆盖权益和时间计算，CI 执行安装、类型检查、测试和构建。

## 6. 验收与观察

### 功能验收

- 新旧访问码都不因日期失效。
- 月卡、季卡、年卡只在总分钟耗尽时停止。
- 同一会话结算两次只扣一次。
- 额度不会被扣成超过总额度。
- 报告接口不再返回 `mock-deepseek` 或模拟趋势。
- 首页隐私说明默认勾选，取消后不能开始监督。

### 异常路径

- 会话已结束时重复请求返回成功跳过。
- 数据库额度更新和会话结束不会只成功一半。
- 前端修改持续时间和 AI 次数不影响服务端结算。
- 未确认隐私说明时服务端拒绝创建新会话。

### 数据验证

- 迁移清空所有现有访问码到期时间。
- 迁移将套餐和访问码报告等级统一为 `basic`。
- 会话保存隐私说明版本和确认时间。

### 工程验证

- 类型检查通过。
- 业务规则测试通过。
- 生产构建通过。
- 新环境 schema 和旧环境 migration 同步。

## 7. 风险和回滚

- 部署应用前必须先执行数据库迁移，否则新会话隐私字段和结算 RPC 不存在。
- 永久有效会增加长期未使用权益负债，后续如调整必须只影响新售权益或得到用户明确同意。
- 已结束的历史标准/高级报告会在重新打开时以基础报告展示。
- 如 RPC 上线异常，可回滚应用并恢复旧结算逻辑，但应先核对已经完成的会话，避免重复扣减。

## 8. 实施后回写

- 实际改动：
  - 访问码创建、验证和改套餐统一为永久有效总时长，移除每日额度操作。
  - 新增服务端权益计算工具；分析和心跳会把当前会话运行时间计入额度判断，额度耗尽时自动结束。
  - 新增数据库原子结算函数；会话状态和已用分钟一次提交，同一会话可安全重试。
  - 结算不再采用客户端提交的结束时间、持续分钟、AI 次数和报告等级。
  - 所有套餐和历史访问码统一为真实基础报告，删除模拟高级趋势输出。
  - 首页默认勾选准确的隐私说明；会话记录说明版本和确认时间。
  - 增加 npm 锁文件、Vitest 权益测试和 GitHub Actions 构建检查。
- 验证结果：
  - TypeScript 类型检查通过。
  - 5 项权益和时间边界测试通过。
  - Next.js Lint 无错误或警告。
  - Next.js 生产构建通过。
  - 新环境 schema 和旧环境 migration 已同步；尚未连接真实 Supabase 执行 RPC 集成验证。
- 与原方案的差异：
  - 没有写“24 小时删除”，因为当前根本不持久保存视频或截图；改为准确说明单帧处理、第三方 Qwen 和记录/报告留存。
  - 没有在本轮强行升级 Next.js 大版本，避免把高风险兼容改造混入权益地基。

  - 极端并发开始两个会话时仍缺数据库级单活约束；原子结算不会超扣，但可能短暂同时使用。
  - 正式隐私政策、监护人授权、共享后台密码、持久限流和清理接口签名仍未完成。
