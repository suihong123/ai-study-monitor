## 2. 触发问题

- 发生了什么：本机验证已通过，但托管平台差异与真实设备行为仍是生产上线门禁。
- 证据来源：2026-07-29 隔离数据库验收记录和本轮负责人明确要求。
- 影响的角色：家长、孩子、运营管理员和上线执行者。
- 影响的核心流程：测试资源隔离 → 托管迁移 → 测试部署 → 真机接管 → 生产上线决策。
- 影响的业务/质量指标：权益准确性、重新绑定成功率、旧环境停止率、数据库审计完整性。
- 不处理的后果：可能在生产才发现权限、网络、浏览器后台任务或摄像头停止行为与本地验证不同。

## 3. 本次目标

- 目标：建立与生产完全隔离的可执行测试环境，完成托管 Supabase 验证，并推动真机 8 场景形成可追溯证据。
- 成功标准：
  - 独立托管 Supabase 和独立测试地址明确且不会交叉连接生产；
  - migration 18、只读验证、19 码快照、RLS/授权、真实并发和回滚在托管环境通过；
  - 真机 8 场景均填写实际结果和证据，尤其旧环境摄像头、声音、心跳和分析请求全部停止；
  - 工程检查继续通过，生产上线及回退方案完备。
- 本次范围：测试资源、环境变量隔离、防误连检查、托管数据库验证、真机验收支持、明确缺陷修复和验收文档。
- 明确不做：生产数据库、生产部署、主分支合并、未经确认推送、规则调整、新身份能力或扩大重构。

## 4. 规则与口径

- 业务规则保持：任意连续 15 天最多免费重新绑定 10 次，两次成功至少间隔 60 秒，不扣监督时长。
- 用户端主文案保持“访问码15天内最多可免费重新绑定10次。”
- 测试 Supabase 和测试部署只能使用脱敏数据及专用测试码。
- 浏览器端只能接触公开 Supabase URL 和 anon key；service role、数据库密码、后台密码及模型密钥只能用于服务端环境。
- 测试域名与 Supabase project ref、生产域名与生产 project ref 必须双向防误连。

## 5. 方案摘要

- 建议方案：优先创建独立 Supabase 测试项目和独立 Vercel Preview/测试项目；从 v0.8 schema 初始化，导入 19 码脱敏数据，再执行 migration 18 与托管验收。
- 备选方案：如无法自动创建外部资源，输出负责人可直接执行的最简创建步骤、变量清单、SQL 顺序和证据模板，并停在需要登录/权限的位置。
- 选择理由：独立项目能避免 Preview 继承生产变量和误操作生产数据。
- 主要风险：
  - 外部平台登录、配额或组织选择需要负责人参与；
  - Preview 默认变量作用域可能继承生产项目中的 Preview 配置；
  - 真机浏览器调试、摄像头指示和后台请求必须由实体设备确认。
- 回滚/降级方式：测试失败时删除或停用测试部署，重建测试 Supabase；生产保持 v0.8 不动。
