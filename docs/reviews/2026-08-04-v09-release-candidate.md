## 2. 触发问题

- 发生了什么：Release Audit 发现工作树未收口、Qwen 原始请求/响应日志、文档中的真实访问码、发布文档状态与迁移顺序不一致，以及 2 个 High 依赖风险。
- 证据来源：Git 状态、全仓扫描、迁移/schema 对比、`npm audit --omit=dev`、自动测试和生产构建。
- 影响的角色：项目负责人、发布执行人、家长/孩子、系统维护者。
- 影响的核心流程：候选提交 → 数据库迁移 → 应用部署 → 生产验收 → 回滚。
- 影响的业务/质量指标：数据与权益一致性、隐私、发布可追溯性、服务稳定性。
- 不处理的后果：生产发布不可复现，模型输出可能进入平台日志，真实访问码可能进入版本历史，迁移 19 可能被遗漏。

## 3. 本次目标

- 目标：只关闭已确认的 5 个 P1 发布门禁，形成可复现、可审计的 v0.9 Release Candidate。
- 成功标准：工作树分类完成；敏感日志和真实标识清除；文档口径一致；迁移顺序明确；完整工程验证通过；依赖风险形成可执行结论。
- 本次范围：工作树整理、日志脱敏、资料脱敏、发布文档统一、依赖审计、自动验证。
- 明确不做：不开发新功能、不改变重新绑定规则、不迁移或部署生产、不推送、不打 Tag、不修改生产环境变量。

## 4. 规则与口径

- 业务规则不变化：15 天内最多 10 次成功重新绑定、成功间隔至少 60 秒、重新绑定免费且不扣监督分钟、单环境有效。
- 数据/指标口径不变化：访问码权益、会话、识别记录、报告、提醒和结算均沿用已验收实现。
- 兼容旧数据：完整 schema 与 migration 18/19 保持一致，生产迁移必须在显式事务中完成。
- 隐私、安全或权益影响：移除模型内容日志和真实访问码；不得输出或修改任何生产密钥和真实数据库访问码。

## 5. 方案摘要

- 建议方案：按 A/B/C/D 分类收口文件；Qwen 控制台日志仅保留无内容元数据；验收资料脱敏；统一 Known Limitation 和事务发布顺序；不在未确认情况下升级框架。
- 备选方案：无。本轮范围已由项目负责人明确。
- 选择理由：以最小变更关闭发布门禁，不重新打开功能开发。
- 主要风险：文档误写已完成事实；敏感扫描漏报；框架安全修复需要跨 major。
- 回滚/降级方式：所有编辑保留在未提交工作树；提交前可逐文件复核，不触碰任何生产资源。

## 6. 验收与观察
