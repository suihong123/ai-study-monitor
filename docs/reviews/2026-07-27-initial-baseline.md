# 优化前复盘：首次项目全景盘点

> 日期：2026-07-27
> 状态：已完成
> 代码基准：`07f7d42`
> 关联范围：全项目

## 1. 当前基线

- 项目已具备访问码、摄像头监督、Mock/Qwen 识别、动态提醒、会话结算、报告和运营后台的完整 MVP 闭环。
- 代码最近一轮重点是习惯趋势、模型配置、摄像头兼容、后台体验、总时长套餐和开始/结束声音。
- 仓库原 README 以功能和部署说明为主，缺少业务阶段、核心流程、指标口径、风险优先级和固定迭代机制。
- 当前没有线上环境、真实用户、收入、转化、留存或供应商账单信息。

## 2. 触发问题

项目需要从“不断追加功能”转为“每次先基于共同事实复盘，再做可验证迭代”。如果没有统一基线，后续容易把历史设计、Mock 能力和当前业务混为一谈。

本次盘点还发现：

- 月卡/年卡名称与统一 3 个月有效期不一致；
- 改套餐不同步总时长和有效期；
- 会话结算和额度扣减不是原子事务；
- 标准/高级报告仍为 Mock；
- 儿童摄像头场景的同意与第三方处理流程在仓库中没有证据；
- 没有测试、CI 和依赖锁文件。

## 3. 本次目标

- 建立项目、业务和技术共同基线；
- 明确哪些是事实、判断和未知；
- 固化每次优化前的复盘和沟通方式；
- 给出下一阶段优先级，不在本轮修改业务代码。

## 5. 结论

项目当前是功能较完整、但商业与规模化基础尚未补齐的 MVP。下一轮建议先统一套餐权益与会话结算，再用真实线上数据验证摄像头成功率、可信监督、纠错率、提醒恢复和复用；不建议先扩展更多报告样式。
